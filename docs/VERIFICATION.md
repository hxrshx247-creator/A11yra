## Not verified yet

- Clean-checkout Docker Compose startup and Nginx behavior with the built frontend.
- Running Alembic migrations against live PostgreSQL and running pytest and Playwright against the Compose stack. The Compose verification job is configured in CI. Docker and WSL were unavailable on the local host.
- Hosted backup retention and deletion, which depend on the deployment operator.
- Timing differences between known-account and unknown-account authentication requests. Tests compare status codes and messages.

## Known limitations

- Published readers share the teacher application’s origin. A separate origin would provide another isolation boundary.
- The application permits the current bundled reader assets by hash. A snapshot from an older asset version may need to be republished after an asset change. The updated link attributes apply when a snapshot is published.
- Revocation prevents future server responses for the link. A previously downloaded copy or an already displayed page can remain readable on its recipient’s device.
- One API worker coordinates private files, retention and rate limits. The public audit deadline can return while bounded synchronous work finishes in its worker thread. Timed-out processing is checked before usage is recorded.
- Retention sweeps remove expired live data. A deployment operator is responsible for service logs and optional backups.
